# kubernetes/

Flux syncs this directory from `main`. General rules are in the root `CLAUDE.md`.

## Cluster

kubeadm cluster (static pods for etcd/apiserver), Kubernetes v1.36.1, containerd 2.2.1,
Flannel CNI (no NetworkPolicy support). Flux v2.7.5 (source, kustomize, helm and
notification controllers; no image automation).

| Node    | Role          | IP            | Arch  | Hardware                   | OS           |
|---------|---------------|---------------|-------|----------------------------|--------------|
| lenovo1 | control-plane, untainted | 192.168.30.10 | amd64 | Lenovo ThinkCentre M720q   | Ubuntu 24.04 |
| lenovo2 | worker        | 192.168.30.11 | amd64 | Lenovo ThinkCentre M720q   | Ubuntu 24.04 |
| pi5     | worker        | 192.168.30.12 | arm64 | Raspberry Pi 5             | Ubuntu 24.04 |

Use multi-arch images, since pi5 is arm64. Every workload has resource requests (request
about the observed peak, memory limit about 2x, no CPU limits), so the scheduler spreads
them by allocatable. Kubelet reservations and the removed taint on lenovo1 are set by hand,
see `docs/kubernetes-nodes.md`. The iGPU (`gpu.intel.com/i915`) exists only on the Lenovos.

Storage: static NFS PersistentVolumes from TrueNAS for files and app configs, and the
`local-path` StorageClass (node-local disk, `Retain`, not the default) for databases.
A local-path volume pins its pod to the node it was created on.

Network: nodes are on VLAN 30 (`192.168.30.0/24`). MetalLB pool `192.168.30.200-240`.
Envoy Gateway on `192.168.30.200`.

## Access

Read-only ServiceAccount `claude/claude-readonly` via `KUBECONFIG` in
`.claude/settings.local.json` (gitignored). Bound to the built-in `view` ClusterRole
plus `claude-readonly-extra` (nodes, PVs, CRDs, Flux, Prometheus Operator and Gateway API
resources)
and `GET` on the Prometheus Service proxy in `monitoring`, for PromQL queries:
`kubectl get --raw '/api/v1/namespaces/monitoring/services/kube-prometheus-stack-prometheus:9090/proxy/api/v1/query?query=up'`.
No access to secrets.
Never run `kubectl apply/create/delete/patch/edit/exec` or `flux reconcile/suspend`.

## Flux layout

| Kustomization | Path | Interval | Prune | dependsOn | Defined in |
|---|---|---|---|---|---|
| `flux-system` | `./kubernetes/clusters/homelab` | 10m | true | | `clusters/homelab/flux-system/gotk-sync.yaml` |
| `infrastructure` | `./kubernetes/infrastructure` | 60m | true | | `clusters/homelab/infrastructure.yaml` |
| `apps` | `./kubernetes/apps` | 5m | true | `infrastructure` | `clusters/homelab/apps.yaml` |

The GitRepository `flux-system` polls `main` every minute over SSH (deploy key).
`clusters/homelab/flux-system/` is generated by `flux bootstrap`. Do not edit it,
except for `spec.path` in `gotk-sync.yaml` when the bootstrap path moves.

`infrastructure/` and `apps/` have **no** root `kustomization.yaml`. Flux generates
one and includes every subdirectory, so a new directory with its own
`kustomization.yaml` is synced automatically. There is no root list to update.

## Contents

### Infrastructure (`infrastructure/`)

- **cert-manager** v1.19.2: `ClusterIssuer letsencrypt-prod`, Route53 DNS-01 for
  `magelssen.io`. The AWS credentials (`cert-manager/cert-manager-iam-creds`) were
  created manually and are not in Git.
- **envoy-gateway** v1.9.3 in `envoy-gateway-system`: the Gateway API controller and CRDs

  Gateway `main` on `.200` (via the `EnvoyProxy` resource): listener `http` only redirects
  to HTTPS, listener `https` serves `*.magelssen.io` with one wildcard certificate
  (`wildcard-magelssen-io-tls`) and accepts HTTPRoutes from all namespaces. A
  `BackendTrafficPolicy` turns off Envoy's 15s request timeout for the whole Gateway
- **metallb** 0.15.3: L2, pool `main-pool`
- **external-secrets** 1.3.1: `ClusterSecretStore aws-ssm` (AWS SSM Parameter Store,
  `eu-west-1`, paths `/homelab/<namespace>/<name>`). The IAM key
  (`external-secrets/aws-ssm-credentials`) was created manually and is not in Git. How to
  add a secret: `docs/secrets.md`
- **claude-readonly**: the read-only ServiceAccount and RBAC for Claude Code
- **flux-notifications** (in `flux-system`): a `github` Provider and an Alert for all
  Kustomizations, so each commit on `main` gets a GitHub commit status per Kustomization
  (applied or failed). Logs in as the GitHub App `larma-homelab-flux` (commit statuses only); its
  private key is in SSM (`/homelab/flux-system/github-app-private-key`)
- **local-path-provisioner** v0.0.37: upstream manifest in the repo, patched to `Retain`
  and a pinned busybox. Volumes under `/opt/local-path-provisioner` on each node
- **intel-gpu-plugin** v0.37.1: upstream DaemonSet in the repo, on the amd64 nodes only.
  Pods ask for `gpu.intel.com/i915: 1` and get `/dev/dri/renderD128`. Up to 10 containers
  share each iGPU (`-shared-dev-num=10`). The `render` group is GID 993 on both Lenovos
- **cloudnative-pg** chart 0.29.1 (operator 1.30.1) in `cnpg-system`: the operator only.
  One Postgres `Cluster` per app, defined in the app's folder, on `local-path`
- **kube-prometheus-stack** 92.14.1 in `monitoring`: Prometheus (pinned to pi5, 20Gi
  local-path, 30d / 15GB), Grafana on `grafana.magelssen.io` (1Gi local-path, generated

`envoy-gateway-system/main`, on `<name>.magelssen.io` (homarr uses `dashboard.magelssen.io`,

  `encoded-video` (mounted inside `/data`) and `model-cache`, created by init containers.
  CloudNativePG `Cluster` `immich-db` (1 instance, Postgres 18 + VectorChord, `local-path`

## Working rules

- Conventions: one directory per component, one file per resource type
  (`namespace.yaml`, `helmrepository.yaml`, `helmrelease.yaml`, `service.yaml`,
  `httproute.yaml`, `backend.yaml`, `kustomization.yaml`).
- Run `kubectl kustomize <dir>` on every directory you change before saying you are
  done. For `clusters/homelab`, `infrastructure` and `apps`, build with a generated root
  `kustomization.yaml` in a scratch copy, since Flux generates it. Also run the
  `kubernetes` check from `docs/github.md` (flux-schema), which a pull request must pass.
- All Kustomizations have `prune: true`. A Kustomization that points to a path that
  exists but has wrong or incomplete content deletes resources from the cluster.
  - Never move files and change paths in the same step. Use copy, switch path, verify,
    then delete the old copy, each as its own PR.
  - Never rename a Kustomization in place. Deleting a Kustomization with
    `prune: true` deletes everything it manages. Set `prune: false` first, add the new
    one, then remove the old one.
- Before and after risky merges, snapshot namespaces, workloads, HelmReleases and each
  Kustomization's `.status.inventory` and diff them.

## Troubleshooting

Start with:

```sh
flux get all -A
kubectl get events -A --sort-by=.lastTimestamp
```

Without the `flux` CLI: `kubectl get kustomizations,gitrepositories,helmreleases,helmrepositories -A`.

Then `kubectl describe` the failing resource, and `flux logs` or
`kubectl logs -n flux-system deploy/kustomize-controller` (or `helm-controller`).

Expected noise: right after a new commit, `apps` can show `Ready=False` with
`DependencyNotReady` ("dependency 'flux-system/infrastructure' revision is not up to
date") until `infrastructure` has applied the same revision. It retries after 30s.

Both Kustomizations use `wait: true` (timeout 10m): they are Ready only when everything they
apply is healthy. A `Ready=False` with "health check failed" names the object that is not
ready; describe that object. While `infrastructure` is not Ready, `apps` does not apply new
commits, so a stuck infrastructure component blocks app changes.
