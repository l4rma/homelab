# Kubernetes

A bare-metal cluster built with kubeadm and managed with Flux. Everything in this
directory is synced to the cluster from the `main` branch.

## Cluster

| Node | Role | Hardware | Arch |
|---|---|---|---|
| `lenovo1` | Control plane | Lenovo ThinkCentre M720q | amd64 |
| `lenovo2` | Worker | Lenovo ThinkCentre M720q | amd64 |
| `pi5` | Worker | Raspberry Pi 5 | arm64 |

- Kubernetes v1.36.1 (kubeadm), containerd, Ubuntu 24.04
- Flannel CNI
- MetalLB in L2 mode for LoadBalancer services
- Envoy Gateway (Gateway API) on `192.168.30.200` for all HTTP(S) traffic
- Storage: NFS from TrueNAS for files, `local-path` (the node's own disk) for databases.
  See [docs/storage.md](../docs/storage.md)

The cluster mixes amd64 and arm64, so all images must be multi-arch. Node settings
(kubelet reservations, taints): [docs/kubernetes-nodes.md](../docs/kubernetes-nodes.md).

## Directories

| Path | Contents |
|---|---|
| [`clusters/homelab/`](clusters/homelab/) | Flux entrypoint. `flux-system/` is generated by `flux bootstrap`. `infrastructure.yaml` and `apps.yaml` define the Kustomizations below. |
| [`infrastructure/`](infrastructure/) | Cluster add-ons, one directory each: cert-manager, Envoy Gateway, MetalLB, External Secrets, CloudNativePG, kube-prometheus-stack, metrics-server, local-path-provisioner, the Intel GPU plugin, and the read-only RBAC for Claude. |
| [`apps/`](apps/) | Applications, one directory each. Some run in the cluster. Others run on Proxmox and are only routed through the cluster's gateway. |

Each component has its own directory with one file per resource type
(`namespace.yaml`, `helmrelease.yaml`, `httproute.yaml` and so on) and a
`kustomization.yaml` listing them. `infrastructure/` and `apps/` have no root
`kustomization.yaml`: Flux generates one that includes every subdirectory, so adding
a directory is enough to deploy a new component.

## Flux

Flux was bootstrapped with `flux bootstrap github` and keeps its own manifests in
`clusters/homelab/flux-system/`.

| Kustomization | Path | Interval | Depends on |
|---|---|---|---|
| `flux-system` | `kubernetes/clusters/homelab` | 10m | |
| `infrastructure` | `kubernetes/infrastructure` | 60m | |
| `apps` | `kubernetes/apps` | 5m | `infrastructure` |

- The `flux-system` GitRepository polls `main` every minute over SSH with a deploy key.
- All Kustomizations use `prune: true`, so removing a manifest from Git removes it
  from the cluster.
- Helm charts are installed through `HelmRepository` and `HelmRelease` resources.

### Exposing a service

Every service gets a hostname under `magelssen.io`, through one shared Gateway
(`infrastructure/envoy-gateway/`):

1. The Gateway `main` listens on `192.168.30.200` (a MetalLB IP). Port 80 only
   redirects to HTTPS. Port 443 terminates TLS with one wildcard certificate,
   `*.magelssen.io`, which cert-manager gets from Let's Encrypt with a DNS-01
   challenge in Route53.
2. Each app has an `httproute.yaml`: an `HTTPRoute` that attaches to the Gateway's
   `https` listener and sends its hostname to the app's `Service`.
3. A DNS record in Pi-hole points the hostname to `192.168.30.200`.

For services outside the cluster, the HTTPRoute points to an Envoy Gateway `Backend`
(`backend.yaml`) with the external IP and port instead of a `Service`. HTTPS backends
with self-signed certificates set `tls.insecureSkipVerify` and the `wss` app protocol,
so Envoy talks HTTP/1.1 to them and websockets work.

Envoy's default 15-second request timeout is turned off for the whole Gateway, so
websockets, video streams and large uploads are not cut off.
