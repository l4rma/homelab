# Kubernetes

A bare-metal cluster built with kubeadm and managed with Flux. Everything in this
directory is synced to the cluster from the `main` branch.

## Cluster

| Node | Role | Hardware | Arch |
|---|---|---|---|
| `lenovo1` | Control plane | Lenovo ThinkCentre M720q | amd64 |
| `lenovo2` | Worker | Lenovo ThinkCentre M720q | amd64 |
| `pi5` | Worker | Raspberry Pi 5 | arm64 |

- Kubernetes v1.36.1 (kubeadm), containerd, Ubuntu 24.04
- Flannel CNI
- MetalLB in L2 mode for LoadBalancer services
- Persistent storage over NFS from TrueNAS

The cluster mixes amd64 and arm64, so all images must be multi-arch.

## Directories

| Path | Contents |
|---|---|
| [`clusters/homelab/`](clusters/homelab/) | Flux entrypoint. `flux-system/` is generated by `flux bootstrap`. `infrastructure.yaml` and `apps.yaml` define the Kustomizations below. |
| [`infrastructure/`](infrastructure/) | Cluster add-ons, one directory each: cert-manager, ingress-nginx, MetalLB, External Secrets, and the read-only RBAC for Claude. |
| [`apps/`](apps/) | Applications, one directory each. Some run in the cluster. Others run on Proxmox and are only routed through the cluster's ingress. |

Each component has its own directory with one file per resource type
(`namespace.yaml`, `helmrelease.yaml`, `ingress.yaml` and so on) and a
`kustomization.yaml` listing them. `infrastructure/` and `apps/` have no root
`kustomization.yaml`: Flux generates one that includes every subdirectory, so adding
a directory is enough to deploy a new component.

## Flux

Flux was bootstrapped with `flux bootstrap github` and keeps its own manifests in
`clusters/homelab/flux-system/`.

| Kustomization | Path | Interval | Depends on |
|---|---|---|---|
| `flux-system` | `kubernetes/clusters/homelab` | 10m | |
| `infrastructure` | `kubernetes/infrastructure` | 60m | |
| `apps` | `kubernetes/apps` | 5m | `infrastructure` |

- The `flux-system` GitRepository polls `main` every minute over SSH with a deploy key.
- All Kustomizations use `prune: true`, so removing a manifest from Git removes it
  from the cluster.
- Helm charts are installed through `HelmRepository` and `HelmRelease` resources.

### Exposing a service

Every service gets a hostname under `magelssen.io`:

1. An `Ingress` with `ingressClassName: nginx` and the annotation
   `cert-manager.io/cluster-issuer: letsencrypt-prod`.
2. cert-manager requests a Let's Encrypt certificate and proves ownership of the
   domain with a DNS-01 challenge in Route53.
3. ingress-nginx, on a MetalLB IP, terminates TLS and routes to the `Service`.

For services outside the cluster, the `Service` has no selector and points to a
manual `Endpoints` object with the external IP.
